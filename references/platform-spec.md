# 微信动态表情规格

本技能主流程**只交付 GIF 本体**，因此 §1 是唯一必须遵守的硬规格。§2/§3 是可选投稿包扩展的知识存档，非用户明确要求不执行。规格以提交页实时提示为准；历史教程里的 500KB / 200KB 是早年标准，按最严的做不会错。

---

## 1. 单张主图 GIF（本技能交付物）

| 项 | 规格 | 本技能实现 |
|---|---|---|
| 尺寸 | **240 × 240** | `frame_240()`，画布 240，角色 `thumbnail((225,203))` |
| 格式 | GIF，透明背景 | `transparency=255` + `disposal=2` |
| 体积 | 卡通/其他类 **≤100KB**（真人/截屏 ≤500KB） | 自适应调色板，脚本安全线 `98_000` 字节 |
| 帧数 | 建议 6 帧，全部互不相同 | 3×2 sprite sheet，导出前查 `unique_frames` |
| 循环 | 无限循环 `loop=0` | `encode_gif()` |
| 帧时长 | 总时长约 2 秒，峰值帧停顿略长 | `[350,250,250,450,250,350]` ms |
| 命名 | `01.gif` … `24.gif`（投稿时主图缩略图一一对应） | `export_gifs.py` |
| 背景 | 透明；深色聊天背景下可读 | 白底抠图 + 深灰底验收图 |

### 为什么必须透明 + 检查深色背景

聊天客户端有深色模式。白底残留、轮廓 halo 白边、封闭白洞在白底预览里看不出来，深色背景下极其刺眼。历史项目 QA 全绿但深色模式 5 张有白边，是用户肉眼发现的。**导出后必须生成深灰底逐帧预览并实际查看。**

### 体积控制

`encode_gif()` 从 `COLOR_STEPS = [255,224,192,160,128,96,64]` 逐档挑能塞进上限的最高色数。白底 matte 只用于生成共享调色板，不会被写进透明像素。历史实测：无道具约 42KB、带办公桌+电脑约 65.7KB、24 张全套最大 95.4KB，255 色全部通过，通常不需要降色。

### 单张规格常见误解

- **320×320 能不能用**：聊天里「自定义表情」可以（客户端普遍 ≤1MB，尺寸会被缩放），但微信表情开放平台投稿上架不行，必须 240×240。
- **240×240 PNG ≤60KB**：那是「表情单品」规格，不是专辑主图规格，别混用。
- **动态 ≤500KB / 必须 2px 白外描边**：2026 年第三方说法，未找到官方原文。按 ≤100KB 做最稳。

## 2. 专辑级规格（可选扩展）

| 项 | 规格 |
|---|---|
| 张数 | 专辑**只支持 16 或 24 张**；官方《提交表情快速过审经验分享》（2019-12-07）建议做 24 张，发送量数据更高 |
| 动静态 | 一套内全部动态或全部静态，不可混排 |
| 布局 | 按命名顺序，16 张为 4×4，24 张为 **4×6** |
| 排序建议 | 高频表情放前面，相关表情放一堆 |
| 表情名称 | ≤8 汉字、无标点 |
| 含义词 | ≤4 汉字、**同套互不重复**（是搜索词，不是画面台词） |
| 命名 | `01`–`16` 或 `01`–`24`，主图与缩略图一一对应 |

2015 公告 `bulletin_9` 开放了「表情单品」（可不凑套），但专辑仍限定 16 / 24 张。

## 3. 投稿包附加素材（可选扩展）

| 素材 | 规格 | 备注 |
|---|---|---|
| 缩略图 | PNG 120×120 ≤50KB，透明，取各主图首帧 | 与主图一一对应 |
| 表情封面图 | 透明 PNG 240×240 ≤80KB | 表情主体、无装饰性元素/文字、**无杂边**（PS 导出勾「杂边：无」）；为压体积留白底不能过审 |
| 聊天页图标 | 透明 PNG 50×50 | 由封面改尺寸，取角色头部 |
| 详情页横幅 | JPEG/PNG 750×400 ≤80KB | **画面无任何文字**、非透明、非纯白底、色调活泼且与微信底色区分 |
| 命名对照表 | CSV | 名称 / 含义词 / 构图 / 道具 / 辨识点 |
| 上传清单 | Markdown | 各素材位置与状态 |

另需艺术家资料与平台审核，不属于素材制作范畴。

### 字体授权

做投稿素材时优先用 SIL OFL 1.1 授权字体（如 `C:/Windows/Fonts/NotoSansSC-VF.ttf`，思源黑体，`set_variation_by_axes([700])` 设粗体），比微软雅黑等系统字体商用授权更稳，且中文字形覆盖完整、零方框。本技能主流程不叠名字条，只有道具文字可能用到字体。

---

## 4. 「无字版」口径（重要）

**「无字版」= 画面下方不叠加表情名称字幕条，不是画面内零文字。**

- 允许：道具上的精确文字（台历「今天 / 明天」），由本地 Pillow + 字体叠加，不经过 AI。
- 禁止：AI 乱画的水印、落款、签名、名称条、字幕条。
- 历史上把这个口径扩大成「画面零文字」，差点把台历文字方案整个砍掉。术语拿不准先回查历史交付，不要自行扩大用户口径。
