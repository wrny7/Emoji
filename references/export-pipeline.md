# 本地导出管线参数与判据

全部在 `scripts/sticker_lib.py`，纯 Pillow、零积分、可回滚。本文解释每个参数的来历与改动代价。

---

## 1. 白底抠图 `cutout()`

### 默认参数（历史实测，勿轻易改）

| 参数 | 值 | 作用 |
|---|---|---|
| `BG_MIN` | 228 | 主体区：像素 RGB 最小通道 ≥228 才算背景候选（保守，保护浅色毛绒边缘） |
| `BG_MIN_SHADOW` | 205 | 底部阴影带放宽，去掉地面阴影 |
| `BG_SPREAD` | 18 | 「中性」判定：通道极差 ≤18 才算背景候选 |
| `SHADOW_BAND` | 70 | 底部 70 行使用宽松阈值 |
| `EDGE_CLEAR` | 4 | 清掉格子最外 4px，去掉模型画的淡灰接缝 |
| 高斯模糊 | 0.6 | alpha 边缘抗锯齿 |

### 算法

1. 通道运算求出「像影棚纯白」的候选像素：**`BG_SPREAD` 按通道极差判定中性，不按亮度**。暖米白衣服色散 31 → 100% 保留；中性浅灰 / 近白 → 0% 保留。
2. 从格子四边做 flood-fill，只把**与边界连通**的背景候选变透明；封闭在角色内部的白色保留。
3. 可选 `erode_px=1`：`MinFilter(3)` 把 alpha 内缩 1px，吃掉外轮廓浅灰 halo。
4. 可选 `fill_holes=True`：清掉**被深色包围、flood-fill 够不到**的近白封闭块（杯把手 C 形圆孔、文件夹内孔），严格 `min>=235`，不碰米白衣服。
5. 清外 4px → `GaussianBlur(0.6)` → 写回 alpha。

### 三条铁律

1. **绝不靠降低 `BG_MIN` 去救生成失误。** 白底阈值是管线假设，灰底生成图必须重生成或在 prompt 里写死纯白。历史事故：pilot 出了中灰底 ~195，把 `BG_MIN` 从 228 一路降到 120 硬救，结果把角色身上接近中灰的浅色部位（米白毛绒、浅色鞋、袖口）一起判成背景吃掉 —— 「人物没一个完整的」直接原因。这是纯技术失误，赖不着模型。
2. **halo 白边靠形态学腐蚀清，不靠降阈值。** 降阈值会同步吃掉浅色衣料。轮廓 halo 是角色外一圈 RGB 195–231 的浅灰抗锯齿边（flood-fill 到 `BG_MIN=228` 停住，整圈被当角色保留）；封闭白洞是另一类问题。两者用两种独立后处理。
3. **局部问题只用按编号覆写 + 哈希 diff。** 全局把 `BG_MIN` 降到 200 曾导致 48 个文件全变、5 张米白衣服被挖穿，被迫整体回退。

### 局部覆写配方（`config.json` → `cutout_overrides`）

| 症状 | 覆写 | 机制 |
|---|---|---|
| 浅色衣服 / 肚子出现透明缺口 | `{"bg_min":244,"bg_min_shadow":244,"shadow_band":0}` | 关掉底部宽松阴影带，只挖近纯白 |
| 深色模式下轮廓 halo 白边 | `{"erode_px":1}` | 内缩 1px，512→240 缩放后几乎不可见 |
| 杯把手 / 文件夹内孔残留白块 | `{"fill_holes":true}` | 清封闭近白块 |
| 角色贴右边界被清边削掉 | `{"edge_clear":0}` | 关掉外缘清理 |

**透明缺块的排查方法**：缺口连到画面边界、不是封闭内部洞，用「封闭洞」检测查不出来。要直接看指定区域的 alpha 计数 + 边界连通性。历史 01 号 C2 肚子区域 508 个透明 px、C4 794 个，靠「内部洞」检测完全无感。

## 2. 六格切分 `sheet_tiles()`

- 严格校验输入为 `1536×1024`，尺寸不符直接报错（防灰底图 / 错位图混入）。
- `remove_grid_lines()` 清掉格线位置 x∈{511,512,513,1023,1024,1025}、y∈{511,512,513} 上的淡灰分隔线（判据 `165≤min≤max≤248` 且极差 ≤12）。注意有**误报**可能：半身人物下缘的灰像素分三段落在三列，放大复核后再判断，本地清理即可，不必重生成。
- 半身 / 宽场景条目可走 `soften_bottom()` 把底边 28px 的 alpha 渐隐，避免硬切腰线。半身裁腰是设计意图，不是裁切事故。

## 3. 240 排版 `frame_240()`

- 画布 `240×240` 全透明，角色 tile `thumbnail((225,203))` 等比缩放后**居中**。
- `(225,203)` 是历史项目反复调出来的「角色偏小」布局：实际约 203×203，240 成品里人物约 168px 高。
- **不要用 `(236,236)` 放大居中**，也不要对半身裁切图直接套 `thumbnail` —— 宽高比变化会把角色自动放大 1.31 倍（全身系数 0.396 vs 半身 0.521）。半身必须显式锁缩放系数。
- 若做「带名字条」扩展版，用 `top_align=True` 让角色顶部对齐 y=0、文字 y=207；**240 格版式必须复刻导出器的 y 规则，不能想当然居中**，否则文字会压到鞋子。

## 4. 透明 GIF 编码 `encode_gif()`

```python
COLOR_STEPS = [255, 224, 192, 160, 128, 96, 64]
DURATIONS   = [350, 250, 250, 450, 250, 350]   # ms，C4 峰值停顿更长
LIMIT_MAIN  = 98_000                            # 给 100KB 硬线留余量
```

- 从高到低逐档挑**能塞进上限的最高色数**；白底 matte 只用于生成共享调色板，不写进透明像素。
- 必要组合：`save_all=True` + `append_images` + `loop=0` + `disposal=2` + `transparency=255` + `optimize=False`。
- `ind.paste(255, mask=alpha<128)` 把透明像素统一指向调色板 255 号，避免帧间残留。
- 历史实测 24 张全套**全部 255 色通过**、最大 95.4KB，通常不需要降色。场景类动作（办公桌 + 电脑）压力测 65.7KB，仍安全。

## 5. GIF 质检 `inspect_gif()` 的两个坑

1. **`info` 要在迭代前保存**。用 `ImageSequence.Iterator` 时第 0 帧是 P 模式，后续帧会变 RGBA 且丢失 `info['transparency']`。必须先 `info = dict(im.info)` 再 `seek` / 迭代。
2. **`blank_frames` 阈值是 0.02 不是 2.0**。不透明占比是 0–1 的小数，写成 `< 2.0` 会误报全空白。

判决项：`bytes` / `size` / `frames` / `unique_frames` / `loop` / `transparency` / `opaque_pct` / `blank_frames`。

## 6. 姿态量化 `pose_metrics()` / `region_diff()`

| 函数 | 输出 | 用途 |
|---|---|---|
| `pose_metrics()` | 逐帧 alpha 质心 (cx,cy) + bbox 宽高；相邻帧质心位移、宽高变化率；`avg_centroid_shift_px`、`pairs_over_8px`、`pairs_shape_over_10pct` | **姿态证据** |
| `region_diff()` | 相邻帧平均绝对灰度差，按头 (y<110) / 身 (y≥110) 分区 | 辅助诊断 |

**帧差只能证明画面变了，不能证明人物在动。** 脸、单只手、逐格重渲染噪声都会拉高 body 帧差（历史样张 body 8.9–19.7 看着不低，质心位移却只有 1.4–3.8px，实际是六格同一站姿）。技能原话：「人物本身必须运动」。

动作型参考验收线（对齐历史 B 版 10 号 5.91px / 2 对 / 3 对）：
- 平均质心 ≥5px
- ≥8px 的相邻帧对数 ≥2
- 轮廓变化 ≥10% 的相邻帧对数 ≥2
- 跨套首帧差异 ≥10%

**状态型（比心 / 点赞 / 捂脸 / 台历）豁免量化线**，改用分类验收：手势恒定 + 六帧脸变化 / 道具全程可认 + 零 AI 文字 / 峰值帧表情递进。

---

## 7. 入框判据 `edge_crop_ok()`

只有**最外 2px 出现实体不透明像素（alpha ≥200）** 才算真裁切。

旧的 `full_in_frame`（bbox 四边都 >4px）会把半身构图故意裁腰误判为失败，也会把半身袖口 / 浅色残影误杀。留白 <24px 只记 `tight_margin` warning，不判失败 —— 角色仍完整、没被切掉。

## 8. 本地叠字（可选）

`export_gifs.py` 的 `overlay_text()` 在 **512 格阶段**用 Pillow + 本地字体叠字，再缩到 240，保证清晰。配置在 `config.json` 的 `prop_text_overlay`：

```json
{
  "18": {
    "words": ["今天", null, "今天", "明天", "明天", "今天"],
    "box": [180, 300, 360, 415],
    "size": 44,
    "color": "#30415B"
  }
}
```

- `words` 按 C1…C6 顺序，`null` 表示该帧不叠（例如正在翻起的斜页）。
- **叠字前必须先看实际 sheet 确认哪几帧是平放页**。历史项目方案文档假设翻页在 C3，实际生成在 C2，沿用会把字画在斜页上、平页反而空白。
- C6 与 C1 用同一个词，保证循环闭合。
- 中文两字在 240×240 下比英文单词（`TOMORROW`）更清楚，优先中文；降级链「中文 → 英文 → 图形」，全链不经过 AI，所以不存在「AI 写错中文」。

## 9. 返修回归证明

任何局部返修后，对全部 GIF 做 sha256 diff：

```bash
# 返修前
find <workdir>/output/gifs -name '*.gif' -exec sha256sum {} \; | sort > /tmp/before.txt
# 返修后
find <workdir>/output/gifs -name '*.gif' -exec sha256sum {} \; | sort > /tmp/after.txt
diff /tmp/before.txt /tmp/after.txt
```

**只有目标条目的哈希允许变化**，其余必须 byte-identical。历史项目用这招证明过：01 号肚子修复只影响 1 个 GIF；白边修复只影响 5 个 GIF；改名不改画面时 48 个文件全部不变。
