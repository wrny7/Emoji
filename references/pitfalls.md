# 血泪复盘与硬规则

本文是整个流程最值钱的部分。全部来自一次真实项目（Q 版角色 → 24 张微信动态表情）的翻车记录，每条都是花过积分或返工换来的。**遇到相似症状先查本文，别重新踩。**

---

## 0. 核心结论：两类任务不能共用一套工作方式

**不是积分的问题，是把确定性任务和概率性任务用了同一套工作方式。**

| | 本地工程活（0 积分） | 生成活（花积分） |
|---|---|---|
| 性质 | 确定性 | 概率性 |
| 输入 | 固定图片、固定参数 | 一段自然语言描述 |
| 结果 | 可精确预测 | 只能概率靠近 |
| 出错 | 改参数重跑，零成本、可回滚 | 一次调用不可回滚，重来要再花钱 |
| 验证 | 脚本量化，秒级出结论 | 要肉眼看、逐帧核 |
| 正确做法 | 先测量 → 再设计 → 再实现 → 再 QA | 前置约束锁死输出环境 → 一次只验一个变量 → 样张逐条打勾 → 通过才铺开 |

本地活做得好是因为「先测再动手」：配色会不会被抠掉、字号会不会裁切、缩放比例会不会漂移，全先跑实验再定方案。生成活做砸是因为把这一步省了，直接拿 prompt 赌模型输出，然后靠事后打补丁救。**把「写清楚了」当成「能控住」是最根本的错误。**

### 八条具体错误（原复盘结论）

1. **方案没锁定就动手。** 动作设计稿没确认、构图前提（半身/全身、灰底/白底、完整入框）都没定，就跳去生成样张。样张建立在错误前提上，翻车是必然。
2. **生成条件变了，管线没跟着变。** 见 §1。
3. **构图从技术限制倒推，不是从表达需要倒推。** 旧稿 24 条里 20 条用半身，理由是「240 下五指会糊，把手放大」—— 为解决自己的技术麻烦，不是因为动作需要。结果角色被裁得残缺、动作也没了全身配合。
4. **六帧只写了手。** 通篇「C1 垂手 → C2 抬手 → C3 定格 → C6 收回」，躯干、重心、腿、头、眉眼嘴全没写，生成出来当然只有一条胳膊在动。
5. **道具只写了个名字。** 「放大镜」「咖啡杯」四个字交差，没写结构 / 材质 / 配色 / 小配件，也没写「非白非中性灰」，抠图阶段必然出洞。
6. **没有验收清单，先做后验。** 一次铺开 16 套，做完才量化出「相邻帧平均变化只有 10.97%」。正确顺序是先定标准 → 1 套样张逐条打勾 → 通过才铺开。
7. **把「省积分」当成流程目标。** 为不重生成灰底 sheet，宁可降阈值硬抠。省下 2 次调用，赔上整套交付质量。**该重做就重做，补丁不能替代前置约束。**
8. **把没核实的假设当硬约束，还围绕它写整套设计（最危险）。** 见 §2。

## 1. 灰底事故：管线假设被破坏后硬救

**症状**：pilot 样张生成出来是**中灰底 ~195**，而本地抠图管线 `BG_MIN=228 / BG_SPREAD=18` 从第一天起就假设纯白背景。没在 prompt 里写死纯白，也没在生成前检查，事后把阈值一路降到 `BG_MIN=120` 硬救。

**后果**：把角色身上接近中灰的浅色部位（米白毛绒、浅色鞋、袖口）一起判成背景吃掉 → **「人物没一个完整的」**。用 ViewImage 复核时还把棋盘格误读成实底、没看出残缺，QA 也失守。

**规则**：生成产物必须归一化到管线假设再进管线。灰底就重生成或在 prompt 写死 `#FFFFFF`。**绝不靠降低抠图阈值去救生成失误。**

## 2. 源头理解错误：墨镜遮眼（比灰底更危险）

**症状**：v2 动作分解里写「眼睛被墨镜挡住，所以瞪眼/泪目做不了」，据此把整套表情系统设计成「墨镜位移 + 装饰件开合」，24 条全按这个前提写，17 号整条动作重新设计。

**真相**（用户点破后放大基准图核对）：墨镜架在头顶当装饰、**完全不遮眼**；灰蓝大眼完整可见，是表情表达力最强的部位；黄色鸭嘴是兜帽上的静态装饰件、**不是嘴不会开合**；真正的嘴是脸上那张小红椭圆。三处全错，且**从头到尾没打开过那张路径明确、自己文档里反复引用的基准图**。

**为什么更危险**：灰底是执行时没检查，这条是**设计源头就错了，写得越细、错得越远**，一个错误前提污染整节设计 + 24 条表情。

**规则 R9**：凡要写成「做不到 / 必须 / 一律不动」的硬约束，先打开基准图核对再落笔。基准图路径明确就别靠记忆或文字描述推断。

## 3. 口径扩大化：「无字版」

**症状**：用户说「最后用无字版」，被理解成「画面内零文字」，于是把 18 号台历「今天 / 明天」文字方案整个砍掉，改用图形太阳/月牙方案。

**真相**：「无字版」= **不叠加表情名称字幕条**，不是画面内零文字。道具上的文字允许，且由本地字体精准叠加、不经过 AI。这是和墨镜那次同类的源头理解错误。

**规则 R11**：别把用户口径扩大化。术语拿不准先回查历史交付再写硬约束。

**规则 R12**：精确文字走本地 Pillow 叠加，不让 AI 写字。AI 生成中文几乎必错字或糊成脏点，本地字体 100% 正确。240×240 下中文两字比英文单词（`TOMORROW`）更清楚。sprite sheet 里道具页留干净空白色块，导出后按帧叠字。

## 4. 动作幅度与区分度

### 4.1 全身联动不通过

用户反馈「动作幅度小，几个表情区别不大」。量化确认属实：16 套相邻帧平均变化仅 **10.97%**，96px 尺度上质心位移普遍只有 0.5–2.6px，等于头部微动；120 组跨表情首帧对比里 **20 组差异 <8%**。

根因：prompt 为保证「角色身份/大小/位置固定」，把动作约束得过于保守，只写头部倾斜 + 短手臂小幅升降，且多套共用相似站姿。

**解法（B 版验证有效）**：
- 六帧全改成**剪影差异极大的具名姿态名词**（NARROW TALL STANDING / HUNCHED GIGGLE / BENT DOUBLE / THROWN BACKWARD ARMS FLUNG WIDE ONE LEG KICKED UP / DEEP SQUAT / STANDING WIPING A TEAR）。
- 明写 `SILHOUETTE MUST BE DRAMATICALLY DIFFERENT IN EVERY FRAME`。
- `input_fidelity` 从 `high` 降到 `medium`（`high` + 强 IDENTITY LOCK 会压制姿态变化）。
- 结果：平均质心 3.66px → **5.91px（+61%）**，≥8px 对数 1 → 2，出现原版完全没有的单腿抬起、蹲身缩球、前倾、擦泪。

### 4.2 禁用深度方向姿态

「稍等一下」v2 把动作写成「前倾 / 后仰」等深度方向姿态，正面 2D 画面里剪影几乎不变，动作序列断裂，**比只动手掌的 v1 更差**；v3 改成左右侧倾、肩线高低、头歪方向、双臂展开并锁定「宽度 C1→C4 递增、C4 最宽」，成功（质心 3.3px → 5.73px）。「明天再说」写成转身背对还会丢脸。

**规则**：正面视角的 sprite sheet prompt 禁用前倾 / 后仰 / 转身背对 / 后退一步，必须写侧倾、肩线、臂展、头歪这类改变 2D 外轮廓的姿态。

### 4.3 峰值撞型

全辑 C4 峰值姿态要互不撞型。用户不满的往往不是百分比低，而是「不够有戏 / 辨识度低」，验收应以场景化 + 大幅姿态 + 跨表情差异为主。

### 4.4 帧差不能当姿态证据

历史样张 `region_diff` 的 body 8.9–19.7 看着不低，但那是逐格重渲染噪声 + 表情，质心位移只有 1.4–3.8px。**帧差只证明画面变化，不证明人物动作合格。** 姿态看质心位移与轮廓宽高变化。

## 5. 半身构图的两个陷阱

1. **QA 误判**：半身是设计上故意裁腰，旧 `full_in_frame`（bbox 四边 >4px）会把它当裁切事故，还会误杀半身袖口 / 浅色残影。改用 `edge_crop_ok()`：只有最外 2px 出现实体不透明像素才算真裁切；留白 <24px 仅记 warning。
2. **自动放大**：直接把半身裁切图交给 `thumbnail((225,203))`，会因宽高比变化把角色自动放大 **1.31 倍**（全身系数 0.396 vs 半身 0.521），与「角色尺寸不要大」冲突。半身必须显式锁缩放系数。

## 6. 抠图与透明相关事故

| 症状 | 根因 | 修法 |
|---|---|---|
| **肚子 / 浅色衣服缺一块透明** | 底部 70px 阴影带用宽松 `BG_MIN_SHADOW=205`，半身构图米白衣服的近白高光落在带内被判背景，flood-fill 从底边啃进去。缺口**连到边界**，不是封闭内部洞 | 按编号覆写 `{"bg_min":244,"bg_min_shadow":244,"shadow_band":0}`，只挖近纯白 |
| **深色模式轮廓 halo 白边** | AI 白底 sheet 在角色外轮廓留一圈 RGB 195–231 浅灰抗锯齿边，`BG_MIN=228` 停住，整圈被当角色保留 | `erode_px=1` 形态学腐蚀内缩 1px，**不是降阈值** |
| **杯把手 / 文件夹内孔残留白色实心** | 纯白块被深色包围，flood-fill 从边界够不到 | `fill_holes=True`，只清封闭且 `min>=235` 的近白块 |
| **全局改阈值导致 48 个文件全变** | 把默认 `228/205/70` 降到 `200/200/0`，05/16/17 米白衣服被挖穿 | 立即回退默认，改为只给问题条目加按编号覆写 |
| **角色贴右边界被削** | 「清掉格子外 4px」会削掉贴边角色右缘 | `edge_clear=0` 覆写 |
| **空白帧被自动补掉** | 旧 `prepare_sheets.py` 把不透明 <5% 的格子当生成失败自动补帧，「角色走出后只剩空画面」会被直接替换 | 取消自动补帧，或加白名单；本技能不自动补帧，直接报错 |
| **纯白道具整块消失** | flood-fill 抠白底 | prompt 写死非白 / 非中性灰、色散 >20。判断风险要看「纯白是否与外部白底连通」，不是看纯白面积 |

**透明缺块排查法**：直接看指定区域的 alpha 计数 + 边界连通性，别只找封闭洞。历史 01 号 C2 肚子 508 个透明 px、C4 794 个，靠「内部洞」检测完全无感。

## 7. 生成端事故

| 症状 | 根因 | 解法 |
|---|---|---|
| **宽场景跨格 / 空格 / 半截伞** | 把 `WIDE / DISTANT / SIDE-VIEW` 写成 prompt 开头 `READ THIS FIRST`，模型把画布当连续画面铺 | 把 `GRID LAYOUT — 六个独立 512 方格、每格恰好一幅完整独立场景、禁空格/禁跨格` 提到最高优先级并首尾重复；道具精简到 4 件 |
| **灰格线 / 分隔线** | 模型在格线位置画淡灰线 | `CLEAN_SHEET_GUARD` 禁止；本地 `remove_grid_lines()` 兜底 |
| **道具跨帧消失 / 变色 / 人物消失 / 六格同站姿** | prompt 未约束 | `PROP_PERSIST_GUARD` / `MOTION_DRAMATIC`；针对性重做，旧图归档 `_reject/` |
| **右下角淡色工具水印** | ImageGen 在整张画布右下角（C6）注入「AI生成 / WORKBUDDY」 | 水印是近白（min≈242–249、低色散）压纯白底，flood-fill 会整片吃掉。**先验真实导出管线再决定是否重做**，多数不需要花积分。**不要用矩形刷白盖水印**，会切掉 C6 角色右半边 |
| **AI 实际帧序与方案不符** | 方案假设台历翻页在 C3，实际生成在 C2 | 叠字 / 后期叠加前**必须先看实际 sheet** 再定帧映射 |
| **六格身份 / 风格漂移** | 拆成 6 次单格独立生成 | 优先用 3×2 图集；单格是兜底，不保证一致性 |

## 8. 质检脚本自身的坑

1. **`blank_frames` 误报全空白**：把「不透明占比」当百分数（0–1）却和 `2.0` 比较，阈值应为 `v < 0.02`。
2. **`transparency` 丢失**：用 `ImageSequence.Iterator` 时第 0 帧是 P 模式、后续帧变 RGBA 且丢失 `info['transparency']`。质检信息要在迭代前先 `dict(im.info)` 保存。
3. **`grid_line_suspect` 误报**：灰像素分三段落在三列半身人物下缘、y512–514 全白，非贯穿格线。放大复核后本地清理即可。
4. **掌宽 / 手部检测口径错误**：把袖管暖色一起算进手掌，虚高到 59%；改为只在左右手臂区域用严格掌色判定、逐行连续宽度最大值。
5. **反例假阳性**：纯白被深色封闭在内部、flood-fill 够不到，测出 77.7% 假保留。反例必须让纯白与外边界连通。
6. **QA 全绿但深色模式有白边**：数字能查体积 / 帧数 / 透明，查不出视觉 halo。**QA 不能替代肉眼复核深灰底总览。**

## 9. 手型与形象的决策教训

- 为规避模型画崩手部，把方案写成「连指手套、不画五指」，牺牲了点赞 / OK / 比心 / 剪刀手 / 比数 / 握笔的表达能力，方向被用户否掉、定妆照作废。
- 240×240 下五指的真实瓶颈是**指缝够宽 + 手要放大**，不是「画了五指就行」：指缝 1–4px@512 格只数出 1 峰，6px@512（成品 2.4px）才数出 3 峰。示例参考靠「半身 + 大掌（掌宽/头宽 24–39%）」把指缝做到 2–4px 可辨。
- 点赞不依赖数清 4 指，靠「一根明显竖起的拇指 + 收拢拳形轮廓」辨识，但必须半身 + 手部放大。**放大的是手、不是角色整体。**
- 任何形象改动（手、鞋、腿、比例）都会让旧图集不一致 → 全套重生成。改形象前先如实报成本。

## 10. 硬规则全文 R1–R14

| # | 规则 |
|---|---|
| **R1** | **方案先行。** 方案文档未经用户明确确认「不用改」，不调用任何生成工具、不花任何积分。 |
| **R2** | **生成前锁死输出环境**：纯白 `#FFFFFF` 背景、角色完整入框、每格四周留白、不跨边界、不画名字条/水印/落款、定妆照作 `image1`、身份锁。写进 prompt，不靠事后检查。 |
| **R3** | **生成产物归一化到管线假设再进管线。** 绝不靠降低抠图阈值救生成失误；阈值是白底专用，不通用。 |
| **R4** | **构图由动作需要决定。** 默认全身；只有「语义全靠手指精细形态或小道具细节」才用半身，并逐条写明理由。 |
| **R5** | **六帧写全身联动**，每格至少 3 个部位同时变化（躯干/重心腿脚/头颈/双臂双手/表情/道具）；C6 接回 C1。禁用深度方向姿态。 |
| **R6** | **道具写规格不写名字**：结构、材质、主色辅色、细节件，以及「非白 / 非中性灰」。 |
| **R7** | **一次只验一个变量。** 先出 1 套样张，按验收清单逐条打勾；不通过就改，不进下一步。 |
| **R8** | **验收清单前置**：角色四边无裁切、6 帧互异、帧间全身位移可量化、表情有变化、道具跨帧一致、240×240 GIF ≤100KB、透明、无水印、无表情名称字幕条。 |
| **R9** | **凡写「做不到 / 必须 / 一律不动」的硬约束，先打开基准图核对再落笔。** 设计源头错一次，后面全错，写得越细代价越大。 |
| **R10** | **身份结构写进生成 prompt 和验收清单**。模型极易把装饰件画到眼睛上、把静态装饰当嘴开合。 |
| **R11** | **别把用户口径扩大化。** 「无字版」= 不叠加名字条，不是画面内零文字。术语拿不准先回查历史交付。 |
| **R12** | **精确文字走本地叠加，不让 AI 写字。** Pillow + 本地字体 100% 正确；sprite sheet 道具页留干净空白色块。 |
| **R13** | **局部问题用局部覆写 + 哈希 diff 修，绝不动全局默认。** halo 靠形态学腐蚀清，不靠降阈值；封闭白洞与轮廓 halo 用两种独立后处理。 |
| **R14** | **帧差只证明画面变化，不证明人物动作合格。** 姿态证据看质心位移与轮廓变化；QA 数字不替代肉眼深灰底复核。 |

### 补充：授权纪律

用户强调过「反正不扣积分」时，**任何重新生成图集的动作必须先征得其同意**。样张通过后一次性告知预计消耗并取得总授权；授权范围内的批量生成不再逐张请示，但超出范围的重做仍要单独说明。

### 补充：状态型豁免

比心 / 点赞 / 捂脸 / 台历这类状态型动画，靠「手势恒定 + 脸变化 + 道具叙事」表达，质心几乎不动是设计使然，**豁免 R15 式量化动作线**，改用分类验收线。技能禁止的是整体平移缩放伪造动作，表情与手指/翻页属人物本身运动，合规。风险要如实告知：状态型在 240×240 下动感偏弱。
